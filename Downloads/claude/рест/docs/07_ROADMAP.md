# Дорожная карта — ДЕМО ИИ-бота Numero Uno Steakhouse

Фокус карты — **только демо**. Цель одна: дать клиенту (OlegValencia) потрогать бота
на своём кейсе и закрыть сделку. Пока клиент не согласился — полный проект не пилим.

Сайт клиента: https://numerounosteakhouse.com/ (Тильда, ES/EN, бронь Ágora Bookings).

Демо — это **веб-чат по ссылке** (Vercel + OpenRouter), дизайн под их сайт, сценарий
брони как описал клиент: ресторан → дата → время → гости → имя, с доведением до их
живого виджета Ágora. Реальная запись брони не создаётся — показываем связку.

MVP-first: этап 1 — уже живой диалог брони. Этапы 2–3 наслаивают красоту и показ.

> Прогресс — в [`STATUS.md`](STATUS.md). Внутри этапов — чекбоксы acceptance-пунктов.
> Закрытие этапа = git-тег `stage-N-done`.

| # | Этап | Главный артефакт | Зависит от |
|---|---|---|---|
| 0 | Каркас демо | Пустой чат на Vercel отвечает через OpenRouter | — |
| 1 | Движок диалога брони | Бот ведёт бронь ES/EN по сценарию, знает меню/часы | 0 |

## Этап 0 — Каркас демо

**Цель**: рабочая пустая вертикаль, в которой есть всё для сборки демо.

**Что делаем**:
- Node.js проект под Vercel: страница + serverless-функция `/api/chat`.
- Подключение OpenRouter по ключу, ключ в env Vercel (на фронт не светим).
- История диалога на клиенте (serverless без состояния).
- Первый деплой на поддомен `*.vercel.app`.

**Критерии приёмки** (закрытие → tag `stage-0-done`):
- [ ] Страница открывается по HTTPS-ссылке Vercel с любого устройства.
- [ ] В чат можно написать и получить ответ модели через OpenRouter.
- [ ] Ключ OpenRouter не виден на фронте (только в env серверной функции).

---

## Этап 1 — Движок диалога брони

**Цель**: бот реально ведёт гостя по брони на двух языках и знает базовые факты о
ресторанах. Пока без красоты — логика.

**Что делаем**:
- Подготовка базы знаний: меню на сайте — картинка (A3), не текст. Извлекаем текст
  из изображений (ES `/carta` + EN + вино), сверяем, кладём в `data/menu.*.md`.
  Подаём полный текст меню в системный промпт (без БД/RAG, влезает в контекст).
- Промпт на ES/EN: определяет язык гостя и отвечает на нём.
- Сценарий брони по шагам: ресторан (их три) → дата → время → гости → имя.
- Часы (13–16 и 19–24), адреса 3 ресторанов зашиты в промпт.

**Критерии приёмки** (закрытие → tag `stage-1-done`):
- [ ] Гость пишет по-испански → бот отвечает по-испански; по-английски → по-английски.
- [ ] На вопрос про блюдо/меню бот отвечает по реальному меню ресторана.
- [ ] Диалог брони проходит все шаги без пропусков: ресторан → дата → время → гости → имя.
- [ ] Бот корректно разводит 3 заведения и не даёт выбрать несуществующее.
- [ ] В конце бот собирает верную сводку брони (ресторан, дата, время, гости, имя).

## Этап 2 — Дизайн под их сайт + финал Ágora

**Цель**: демо выглядит «как у них», и финал брони убедительно ведёт в их систему.

**Что делаем**:
- Стилизация страницы под numerounosteakhouse.com: лого Numero Uno, красный акцент,
  фото из корня папки (`дизайн.png` как референс).
- Финал брони: сводка + кнопка «Подтвердить», ведущая на реальный виджет Ágora
  нужного ресторана с предзаполненной датой (`?date=YYYY-MM-DD`). Без реальной записи.

**Критерии приёмки** (закрытие → tag `stage-2-done`):
- [ ] Страница визуально похожа на их сайт (лого, цвета, фото), аккуратна на телефоне.
- [ ] Кнопка финала ведёт на виджет Ágora именно выбранного ресторана.
- [ ] Дата из диалога подставляется в ссылку виджета.

## Этап 3 — Деплой и показ клиенту

**Цель**: клиент открывает ссылку, проходит бронь, даёт реакцию.

**Что делаем**:
- Финальный деплой, проверка ссылки с телефона.
- Отправка ссылки клиенту (при желании — 2–3 его частых вопроса вшить в демо).
- Сбор фидбэка, фиксация возражений для дожима сделки.

**Критерии приёмки** (закрытие → tag `stage-3-done`):
- [ ] Ссылка стабильно открывается с телефона и десктопа.
- [ ] Клиент прошёл демо и дал реакцию.
- [ ] Реакция и возражения зафиксированы в «Историю закрытий» STATUS.
