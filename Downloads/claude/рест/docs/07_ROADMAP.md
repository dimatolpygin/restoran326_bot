# Дорожная карта — ИИ чат-бот Numero Uno Steakhouse

Проект для сети стейк-хаусов в Валенсии (3 заведения). Сайт на Тильде, двуязычный
(ES/EN), бронирование через Ágora Bookings, входящие гостей идут ещё и в WhatsApp
на личный номер владельца.

Карта делится на две части:
- **Этапы 0–1 — ДЕМО** (до сделки, бесплатно). Цель — убедить клиента, дать ему
  потрогать бота на своём кейсе. Это инструмент продажи, а не продукт.
- **Этапы 2–7 — ПРОЕКТ** (после согласия/оплаты). Разбиты так, чтобы маппиться на
  пакеты из коммерческого предложения.

Ключевая идея: **MVP-first**. Демо (этап 1) — уже живая вертикаль диалога брони.
Дальше всё наслаивается без перепиливания базы.

> Прогресс всех этапов — в [`STATUS.md`](STATUS.md). Внутри каждого этапа ниже —
> чекбоксы acceptance-пунктов. Закрытие этапа = git-тег `stage-N-done`.

| # | Этап | Главный артефакт | Зависит от |
|---|---|---|---|
| 0 | Каркас демо | Пустой чат на Vercel отвечает через OpenRouter | — |
| 1 | **Демо-бот брони** (продажа) | Ссылка клиенту: бот ведёт бронь ES/EN, дизайн под их сайт | 0 |
| 2 | Бот на сайте Тильда | Виджет чата на боевом сайте, ES/EN, база знаний | 1 |
| 3 | Бронь в Ágora (3 ресторана) | Бот доводит бронь в Ágora, гостю письмо как сейчас | 2 |
| 4 | WhatsApp через Green API | Тот же бот отвечает в WhatsApp на номере владельца | 3 |
| 5 | Админ-панель | Владелец сам правит промпт/акции, видит статистику | 3 |
| 6 | Опции «под ключ» | Бронь прямо в чате, передача оператору, аналитика | 4,5 |
| 7 | Запуск и сопровождение | Всё на бою, владелец обучен, поддержка | 4,5 |

## Этап 0 — Каркас демо

**Цель**: рабочая пустая вертикаль, в которой есть всё для сборки демо.

**Что делаем**:
- Node.js проект (Vercel serverless: страница + функция `/api/chat`).
- Подключение OpenRouter по ключу, ключ в переменных окружения Vercel.
- История диалога держится на клиенте (serverless без состояния).
- Первый деплой на поддомен `*.vercel.app`.

**Критерии приёмки** (закрытие → tag `stage-0-done`):
- [ ] Страница открывается по HTTPS-ссылке Vercel с любого устройства.
- [ ] В чат-окно можно написать сообщение и получить ответ от модели через OpenRouter.
- [ ] Ключ OpenRouter не виден на фронте (только в env серверной функции).

## Этап 1 — Демо-бот брони (инструмент продажи)

**Цель**: клиент открывает ссылку с телефона, проходит бронь голосом гостя и говорит
«вау, хочу». Это то, что закрывает сделку.

**Что делаем**:
- Дизайн страницы под их сайт (референс `дизайн.png`, лого Numero Uno, красный,
  фото из корня папки).
- Промпт бота на двух языках: определяет язык гостя (ES/EN) и отвечает на нём.
- Сценарий брони по шагам, как описал клиент: сначала уточнить ресторан (их три),
  затем дату, время, число гостей, имя.
- База знаний демо: меню (их PDF), часы (13–16 и 19–24), адреса 3 ресторанов.
- Финал брони: бот показывает сводку («суббота, 19:00, 4 чел., ресторан X, на имя Y»)
  и кнопку «Подтвердить», ведущую на их реальный виджет Ágora с предзаполненной датой.
  Реальная запись не создаётся — это демонстрация связки.

**Критерии приёмки** (закрытие → tag `stage-1-done`):
- [ ] Гость пишет по-испански → бот отвечает по-испански; пишет по-английски → по-английски.
- [ ] На вопрос про меню/блюдо бот отвечает по реальному меню ресторана.
- [ ] Диалог брони проходит все шаги: ресторан → дата → время → гости → имя, без пропусков.
- [ ] Бот не даёт выбрать несуществующий ресторан и корректно разводит 3 заведения.
- [ ] В финале показывается корректная сводка брони и кнопка ведёт на виджет Ágora нужного ресторана.
- [ ] Страница визуально похожа на их сайт (лого, цвета, фото), открывается с телефона.
- [ ] Ссылка отправлена клиенту, получен фидбэк.

## Этап 2 — Бот на сайте Тильда

**Цель**: бот живёт на боевом сайте на всех страницах и обоих языках.

**Что делаем**:
- Продакшн-бэкенд бота (вынести из демо в устойчивую версию).
- Встраивание виджета чата через глобальный код в «Настройки сайта» Тильды.
- Полная база знаний: меню (ES/EN), часы, адреса, телефоны, FAQ, при желании вино.
- Определение языка по разделу сайта (ES/EN) и по сообщению гостя.

**Критерии приёмки** (закрытие → tag `stage-2-done`):
- [ ] Виджет чата виден на боевом сайте на страницах ES и EN.
- [ ] Бот отвечает на вопросы по меню/часам/адресам корректно на языке раздела.
- [ ] Ответы соответствуют реальным данным ресторанов (сверка с сайтом).
- [ ] Встраивание не ломает вёрстку сайта на мобильном и десктопе.

## Этап 3 — Бронь в Ágora (3 ресторана)

**Цель**: бот доводит бронь в Ágora по нужному ресторану, гостю приходит то же письмо.

**Что делаем**:
- Логика маршрутизации брони по 3 ресторанам (widget 1684, 1117, третий после
  переезда с CoverManager на Ágora).
- Сбор данных в диалоге и передача в виджет Ágora с предзаполнением (дата и др.).
- Проверка, что письмо-подтверждение уходит гостю штатно через Ágora.

**Критерии приёмки** (закрытие → tag `stage-3-done`):
- [ ] Бронь через бота появляется в панели Ágora нужного ресторана.
- [ ] Гость получает письмо-подтверждение на почту, как при ручной броне.
- [ ] Правильный ресторан выбирается по ходу диалога, бронь не уходит «не туда».
- [ ] Тестовые брони проверены вживую владельцем на всех активных ресторанах.

---

## Этап 4 — WhatsApp через Green API

**Цель**: тот же бот отвечает гостям в WhatsApp на текущем номере владельца.

**Что делаем**:
- Подключение номера владельца через Green API (существующий номер, без потери чатов).
- Переиспользование мозгов бота, добавление уточнения ресторана (номер один на три).
- Тот же сценарий брони и та же база знаний, что на сайте.

**Критерии приёмки** (закрытие → tag `stage-4-done`):
- [ ] Гость пишет на WhatsApp-номер → отвечает бот, текущие переписки не потеряны.
- [ ] Бот в WhatsApp проводит бронь и доводит её в Ágora по нужному ресторану.
- [ ] Владелец может вмешаться в диалог вручную, когда захочет.

---

## Этап 5 — Админ-панель

**Цель**: владелец управляет ботом сам, без разработчика.

**Что делаем**:
- Веб-панель с авторизацией.
- Редактор промпта/тона и текстов бота.
- Управление акциями и спецпредложениями (меняются чаще меню).
- Уведомления владельцу (Telegram или почта) о броне и о просьбе позвать человека.
- Статистика: число обращений, доведённых броней, частые вопросы.

**Критерии приёмки** (закрытие → tag `stage-5-done`):
- [ ] Владелец меняет текст/тон бота в панели → изменение видно в боте без разработчика.
- [ ] Добавленное спецпредложение появляется в ответах бота.
- [ ] При новой броне/просьбе оператора владельцу приходит уведомление.
- [ ] Панель показывает статистику, числа сходятся с реальными обращениями.

---

## Этап 6 — Опции «под ключ»

**Цель**: премиум-функции пакета 3.

**Что делаем**:
- Безкликовая бронь прямо в чате (реверс эндпоинтов виджета Ágora, с оговоркой о хрупкости).
- Живая передача сложного диалога владельцу в момент разговора.
- Углублённая аналитика по обращениям и конверсии в брони.

**Критерии приёмки** (закрытие → tag `stage-6-done`):
- [ ] Гость завершает бронь, не покидая чат; бронь появляется в Ágora.
- [ ] Сложный диалог переключается на владельца в реальном времени.
- [ ] Аналитика отражает воронку от обращения до брони.

---

## Этап 7 — Запуск и сопровождение

**Цель**: всё работает на бою, владелец обучен, поддержка налажена.

**Что делаем**:
- Финальная проверка на бою всех каналов и ресторанов.
- Короткое обучение владельца работе с панелью.
- Договорённость о сопровождении (правки, обновление меню/акций).

**Критерии приёмки** (закрытие → tag `stage-7-done`):
- [ ] Все каналы (сайт + WhatsApp) работают на бою на 3 ресторанах.
- [ ] Владелец самостоятельно вносит правку через панель после обучения.
- [ ] Зафиксирован формат и условия сопровождения.
